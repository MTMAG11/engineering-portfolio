# Autonomous Rocket Project — Weekly Progress Report

### November 9 – November 15, 2026

## Overview

This week I started shifting the avionics work from getting the basic electronics running toward figuring out how the system will physically fit inside the rocket. I already have a V1 flight-computer setup to build around, so the next useful step is making sure the electronics can actually be packaged before adding more complexity.

## Avionics and Mechanical Packaging

I started planning an inert fit-check for the avionics.

The current constraints are:

* 1.25 in internal diameter
* 5.5 in of available length
* Breadboard-based electronics arrangement
* 3D printer available for fit-check parts

The plan is to build the layout in Fusion 360 and use it to check the arrangement before making anything permanent. I also looked into importing existing component models from a library instead of modeling every part from scratch.

I have not finished the CAD model yet. I still need accurate dimensions for the ESP32 board, sensors, SD-card module, connectors, and wiring. The model also needs to account for cable clearance and how the parts will actually be mounted, not just whether the board outline fits inside the tube.

The goal for this stage is only a mechanical fit-check. It is not a final flight-ready avionics assembly.

## Simulator

I did not make a confirmed simulator code change this week.

The current `rocket-simulator` repository is already much further along than the original V0.1 plan. The current codebase documents 6-DOF simulation, vehicle and aerodynamic models, actuator and sensor models, estimation, HIL foundations, dataset generation, and real-flight validation.

The latest visible commit is `e05f4e9` (`V1.2.1`), dated October 9, 2026. The next simulator work should be based on the current repository and verified local state, rather than continuing to use the old V0.1 UI checklist.

The validation is still limited. The repository reports seven real-flight comparisons in the 7–24 kg range and two holdout flights, with a 5.54% holdout apogee RMS error. It does not establish accuracy for sub-1 kg rockets, supersonic flight, or the physical avionics and actuator system.

## Next Steps

* Build the inert Fusion 360 fit-check around the actual dimensions of the electronics.
* Include the board, sensors, SD-card module, connectors, mounting, and wiring clearance.
* Check the layout against the 1.25 in internal diameter and 5.5 in available length.
* Print a simple fit-check part once the CAD dimensions are confirmed.
* Verify the current local simulator checkout against GitHub before deciding on the next software task.
* Keep simulated sensor and HIL functionality separate from real hardware validation.

The main priority is to get the existing avionics into a physical layout that can be checked, rather than adding more firmware features before the packaging is understood.
