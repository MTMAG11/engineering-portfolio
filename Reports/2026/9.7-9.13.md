# Week of 9/7–9/13

This week I mostly worked on the simulator, started cleaning up the avionics logger, and spent some time figuring out how I want the long-term autonomous guidance part of the project to work.

## Simulator

I changed the simulator to use the actual Klima A6 `.eng` motor data instead of a made-up thrust curve. The motor data gives:

* 3.5 g propellant
* 11 g dry motor mass
* 14.5 g total motor mass
* 2.4953 N·s total impulse

I also switched the rocket mass values to grams so they are easier to work with. The current model uses a 150 g dry rocket, so the starting mass is 164.5 g and the mass after burnout is 161 g.

With the current model and `dt = 0.005`, I get:

* Peak thrust: 10.44 N
* Peak ascent acceleration: 54.36 m/s²
* Max velocity: 11.02 m/s
* Max altitude: 8.48 m

These numbers are useful for checking that the simulation is behaving consistently, but the model is still pretty simplified. It doesn't have the 6-DOF physics, aerodynamics, wind, sensor errors, or control system that I eventually want.

I also found a problem with the way the simulation handles the end of the flight. After the rocket hits the ground, it can still report things like `-9.81 m/s²` because the simulation is still technically running. I don't really want that to be considered flight telemetry, so I need to clean up the flight states and stop recording meaningful flight data after ground contact.

The next simulator step is adding better flight telemetry, especially things like time to burnout, time to apogee, burnout velocity/altitude, and other summary values. I also want the simulation to return its results in a consistent structure instead of having other parts of the program reconstruct information from the raw arrays.

## UI / project structure

I started thinking more about the structure for the simulator UI. I don't want the UI to contain the actual physics logic, so the simulator should produce a results object/dictionary and the plotting/UI code should just use that.

The first UI will probably be a basic PySide6 window with simulation controls, Matplotlib graphs, and a flight summary. After that I can build toward the more complicated 2D/3D visualization.

I don't want to start the UI too early though. I need to finish cleaning up the simulation structure and flight states first.

## Avionics

I also worked on the first version of the avionics logger.

The planned V1 hardware is:

* ESP32
* BMP388 barometer
* ICM42688 IMU
* SD card
* timestamps

The BMP388 and ICM42688 will use I2C:

* SDA: GPIO 21
* SCL: GPIO 22
* BMP388: `0x77`
* ICM42688: `0x68`

The SD card caused some problems. The card itself was formatted and recognized, but the wiring wasn't working correctly. I eventually found that the D19-to-DO connection was bad. I also got the SD card working with explicit SPI pin configuration and CS pin 5:

`SCK 18, MISO 19, MOSI 23, CS 5`

So now I'm rewriting `sensor_logger_v1` into an actual V1 logger instead of just keeping the individual sensor/SD tests.

The SD logger is going to stay separate from the flight controller. I want it to act as an observer that records what happened rather than being part of the control system.

## Autonomous guidance

I also spent some time thinking about the long-term autonomous landing system.

The current plan is still:

3-DOF physics → 6-DOF physics → sensor simulation → state estimation → control → guidance → trajectory optimization.

One thing I clarified this week is that these shouldn't all be treated as the same problem. State estimation is figuring out where the rocket actually is from noisy sensor data. Guidance decides where it should go. Control decides how to actually move it there.

I also don't want to jump straight into an AI/ML landing system. I need to first get a deterministic simulation, estimation, and control system working well enough that I can understand what is happening.
